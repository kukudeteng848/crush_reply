# 阶段 3：核心功能拆分（5 个小迭代）

> 阶段 3 是整个项目最复杂的部分，一次性做完不现实。我把它切成 5 个独立小迭代，**每个迭代结束你都能上手玩**，不会出现"做了半个月看不到东西"的情况。

---

## 🗺️ 阶段 3 全景图

```
3A · 登录 + 首页（crush 列表）        ← 我推荐先做
   ↓ 验证：能登录、能看到空列表
3B · 添加/编辑 Crush 信息页
   ↓ 验证：能添加一个 crush 并在首页看到
3C · 聊天界面 + DeepSeek 接入 ⭐核心⭐
   ↓ 验证：输入 crush 的话 → AI 给出回复 → 能复制
3D · 删除 / 头像上传 / 昵称编辑
   ↓ 验证：能删 crush、能删单条消息、能换头像
3E · 收尾打磨（错误状态 / 加载动画 / 风格切换器）
   ↓ 验证：整体流畅，无 bug
```

---

## 📦 3A · 登录 + 首页（预计 1 轮迭代）

**做什么：**
- 用户第一次打开小程序 → 自动静默登录（无需用户点任何按钮，直接拿到微信 OpenID）
- 登录后自动在 `users` 表创建一条记录（昵称默认"我"）
- 跳转到首页（仿微信"我的对话"列表）
- 因为还没添加 crush，显示空状态："你还没有 crush，点 + 添加一个"

**这一步完成后你能：**
- 打开小程序看到登录 → 列表页（仿微信样式）
- 在云开发后台 users 表里看到你的微信 OpenID 已被记录

**不在这一步做：**
- 真正添加 crush（下一步 3B）
- 头像/昵称编辑（3D）

---

## 📦 3B · 添加/编辑 Crush 页（预计 1 轮迭代）

**做什么：**
- 首页右上角 "+" 按钮 → 跳转"添加 Crush"表单页
- 表单字段：
  - 昵称（默认 "crush"，可改）
  - 性别（自由文本框，占位"男 / 女 / 其他"）
  - MBTI（下拉选择，16 种 + "不填"）
  - 星座（下拉选择，12 个 + "不填"）
- 保存 → 写入 `conversations` 表 → 返回首页 → 看到新添加的 crush 卡片

**这一步完成后你能：**
- 自由添加多个 crush（小琳、小琳同事、邻班学姐...）
- 首页能看到他们的列表（仿微信对话列表样式）

---

## 📦 3C · 聊天界面 + DeepSeek 接入（预计 2-3 轮迭代）⭐ 重头戏

**做什么：**
- 点首页某个 crush → 进入聊天界面（仿微信聊天页）
- 顶部：crush 头像 + 昵称
- 底部：输入框 + 风格选择按钮 + "发送"按钮
- 用户输入"crush 发来的话" → 选风格（5 个 emoji 按钮）→ 点发送
- 聊天区显示：
  - 左气泡（crush 说的话，用户刚刚输入的）
  - 右气泡加载动画 → DeepSeek 返回结果 → 显示 AI 建议回复（默认 1 条）
  - 每条回复下面有"复制"按钮
  - 右下角"再来 2 条"按钮 → 再请求 DeepSeek 生成 2 条
- 写入 `messages` 表
- 重新打开此 crush 时能看到所有历史消息

**这一步完成后你能：**
- 体验完整的核心流程：输入 → AI 回复 → 复制
- 这是你做 demo 视频的主场景

**技术细节（不影响你的决策）：**
- DeepSeek 请求走云函数（不能从小程序直接调，因为 API Key 不能暴露在前端）
- 流式响应是否做？v1 先一次性返回（更简单），demo 阶段够用
- Prompt 模板我会在云函数里组合：`基础人格 + 风格指令（来自 styles 表）+ crush 资料 + crush 当前消息`

---

## 📦 3D · 删除 / 头像上传 / 昵称编辑（预计 1 轮迭代）

**做什么：**
- 首页：左滑 crush 卡片 → "删除"按钮（删 conversation + 关联 messages，软删除）
- 聊天页：长按 message → 弹"删除"
- 设置页（新建）：编辑"我"的昵称和头像、编辑某个 crush 的资料和头像
- 头像上传走云存储

**这一步完成后你能：**
- 管理多个 crush（删、改）
- 拥有自己的头像和昵称

---

## 📦 3E · 收尾打磨（预计 1 轮迭代）

**做什么：**
- 加载中骨架屏
- 网络错误友好提示
- 风格切换器优化（默认风格 / 切换风格的交互）
- 历史列表搜索（如果你想要）
- 各种边界状态处理

---

## 🎯 等你拍板

我推荐：**就按顺序从 3A 开始**。每个小迭代做完我们 review 一下效果，再决定下一个迭代的细节。

如果你想调整顺序，告诉我。比如有人会想先做 3C（聊天界面）做个不联数据库的纯前端 demo，但我不推荐——因为没数据流跑通会导致后面返工。
