## 🔴 模块 1：首次启动与隐私协议

### TC-1.1 首次进入小程序，看到隐私协议弹窗
- **前置**：未登录过 / 清除小程序数据
- **操作**：扫码或开发者工具编译进入
- **预期**：
  - ① 首页加载几秒后弹出标题"用户协议与隐私政策"的弹窗
  - ② 弹窗里有"同意"和"不同意"两个按钮
  - ③ 弹窗后台不会闪过任何"未登录"提示
- **失败现象**：弹窗一直不出现 / 出现两次 / 出现前首页可滑动

### TC-1.2 点"同意" → 进入首页正常态
- **前置**：TC-1.1 弹窗已显示
- **操作**：点"同意"
- **预期**：
  - ① 弹窗消失
  - ② 首页顶部"我"卡片出现，显示头像（默认渐变蓝紫）+ 昵称"我"
  - ③ 中部显示空状态：💌 + "还没有 crush 呀" + "点右下角 + 添加 ta"
  - ④ 右下角浮 + 按钮（绿色）可见

### TC-1.3 点"不同意" → 退出
- **操作**：TC-1.1 弹窗里点"不同意"
- **预期**：
  - ① 小程序退出（iOS/安卓真机生效）
  - ② 开发者工具里可能退出失败，800ms 后再次弹窗，不会进首页
- **失败现象**：点了"不同意"但能继续用小程序

### TC-1.4 同意过后再次进入 → 不再弹
- **前置**：已点过"同意"
- **操作**：杀掉小程序重新打开
- **预期**：
  - ① 不再弹隐私协议
  - ② 直接进入首页
- **底层**：本地 storage 存了 `privacy_agreed_v1 = true`

## 🔴 模块 2：我的资料

### TC-2.1 首页点"我"卡片进入"我的资料"
- **操作**：点首页顶部我的横条
- **预期**：
  - ① 跳转到"我的资料"页
  - ② 页面顶部大头像 + "点击更换头像"
  - ③ 三张卡片：① 昵称 ② 我的恋爱档案 ③ 用户协议/隐私政策

### TC-2.2 修改昵称（正常）
- **操作**：点"昵称"行 → 弹输入框 → 改成"小李" → 确定
- **预期**：
  - ① 顶部 toast "已更新" ✓
  - ② 当前页昵称值更新
  - ③ 返回首页"我"卡片显示"小李"
  - ④ 进入任意聊天页右侧我的头像下方显示"小李"

### TC-2.3 修改昵称（输入空字符串）
- **操作**：清空后确定
- **预期**：toast "昵称不能为空"，不保存

### TC-2.4 修改昵称（输入和原值一样）
- **操作**：不改直接确定
- **预期**：无任何提示，不调网络

### TC-2.5 上传头像（相册）
- **操作**：点头像 → 弹"拍照/相册" → 选张图
- **预期**：
  - ① 显示"上传中..."loading
  - ② 完成后 toast "已更新"，头像变成新图
  - ③ 返回首页"我"卡片头像同步
  - ④ 进入任意聊天页右侧我的头像同步

### TC-2.6 上传头像（相机）
- **操作**：选"拍照"
- **预期**：能拍照 + 上传成功

### TC-2.7 上传头像（取消选图）
- **操作**：点头像后又点取消
- **预期**：无任何提示，无 loading 残留

### TC-2.8 编辑"我的恋爱档案"
- **操作**：点"我的恋爱档案" → 选性别"男" → 选 2 个爱好 → 保存
- **预期**：
  - ① toast "已保存"
  - ② 返回我的资料页
  - ③ 下次 AI 生成回复时口吻能用上这些资料
  - ④ 未填性别直接点保存 → toast "请选择性别"

## 🔴 模块 3：添加 / 编辑 / 删除 crush

### TC-3.1 添加 crush（最简：只填性别）
- **操作**：首页点 + → 选性别"女" → 保存
- **预期**：
  - ① toast "已添加"
  - ② 600ms 后自动返回首页
  - ③ 列表里出现一条新 crush，昵称显示"crush"
  - ④ 头像是渐变粉色 + "c"字
  - ⑤ 预览文案"还没有聊天，快开始吧"

### TC-3.2 添加 crush（未选性别）
- **操作**：什么都不选直接点保存
- **预期**：toast "请选择性别"，不保存

### TC-3.3 添加 crush（完整资料）
- **操作**：上传头像 + 填昵称"小美" + 选女 + 95后 + INFJ + 巨蟹座 + 多选 3 个爱好 + 多选 2 个性格 + 多选 2 个聊天风格 + 填"最近提过看《长安三万里》" + 选"认识1-3个月" + 选"暧昧中" + 选"见过1-2次"
- **预期**：保存成功 + 列表里显示"小美" + 头像正常

### TC-3.4 添加 crush（自定义标签）
- **操作**：在"Ta 喜欢什么"点"+ 自定义" → 输入"剧本杀" → 确定
- **预期**：
  - ① 标签出现在列表里
  - ② 自动选中（绿色）
  - ③ 保存后下次编辑能看到这个标签

### TC-3.5 添加 crush（标签反复点选取消）
- **操作**：点"看剧" → 再点"看剧"
- **预期**：第一次变绿，第二次变灰，取消选中

### TC-3.6 添加 crush（自定义后取消选中再保存）
- **操作**：自定义"剧本杀"后再点一次取消选中 → 保存 → 重新进编辑
- **预期**：列表里仍有"剧本杀"标签但未选中 ✗ 实际：自定义标签不保留到下次

> ⚠️ **注意**：当前自定义标签只在选中时持久化（保存的是 `selToArr(sel)`）。如果你取消选中再保存，下次进编辑会丢这个标签。这是产品决策，告诉测试方不算 bug。

### TC-3.7 编辑 crush 资料
- **操作**：首页长按 crush 卡片 → 选"编辑资料" → 改头像 → 改昵称 → 保存
- **预期**：
  - ① 卡片改成新值
  - ② 进入聊天页 navigation 标题也是新昵称
  - ③ 聊天页左侧头像也是新头像

### TC-3.8 删除 crush（二次确认）
- **操作**：长按 → 选"删除" → 弹"删除「小美」？"
- **预期**：
  - ① 标题里能正确显示昵称
  - ② "删除"按钮是红色
  - ③ 点"取消"不会删
  - ④ 点"删除"后 toast "已删除"，列表里消失
  - ⑤ 已删除的 crush 重新进入小程序也看不到

### TC-3.9 删除 crush 后聊天数据保留
- **背景**：软删，实际数据还在云数据库
- **检测点**：删除后没有数据残留在用户可见区域

### TC-3.10 长按提示
- **预期**：首页空状态下面有一行小字"💡 长按 crush 卡片可编辑资料或删除"

## 🔴 模块 4：聊天 · 被动回复

### TC-4.1 进入聊天页（首次，空状态）
- **操作**：列表点 crush 进入
- **预期**：
  - ① 顶部 navigation 标题是 crush 昵称
  - ② 空状态：💬 + "还没和 Ta 聊过" + 两行提示
  - ③ 底部输入栏可见，发送按钮灰色
  - ④ 风格 pill 一行 5 个可滑动
  - ⑤ 黄色"想主动找 ta 聊"入口

### TC-4.2 选择风格 pill
- **操作**：点"暖心" pill
- **预期**：
  - ① pill 变绿色 + 弹一下动画
  - ② 黄色入口下方文案不变（仍显示意图等）

### TC-4.3 输入消息 → 发送（首次生成）
- **操作**：粘贴"今天好累啊" → 发送按钮变绿 → 点发送
- **预期**：
  - ① 左侧出现白色气泡 "今天好累啊"
  - ② 右侧出现绿色卡片，标题"AI 建议" + 右上角"🤗 暖心"
  - ③ 显示"思考中..."动画
  - ④ 几秒后出现 1 条建议 + "复制"按钮
  - ⑤ 下方有"再来 2 条"按钮
  - ⑥ 输入框被清空

### TC-4.4 复制建议
- **操作**：点"复制"
- **预期**：
  - ① toast "已复制"
  - ② 剪贴板里是这条文案
  - ③ 云端记录 selectedText（下一轮 AI 能看到上一轮"我"说了什么）

### TC-4.5 再来 N 条
- **操作**：有 1 条 → 点"再来 2 条"
- **预期**：
  - ① 按钮变成 mini 思考中动画
  - ② 新增 2 条 suggestion 追加到同一张绿卡片
  - ③ 不出现新一轮对话
  - ④ "再来 2 条"按钮消失（已满 3 条）

### TC-4.6 切换风格再生成
- **操作**：发完一条 → 切到"幽默" → 再发一条新消息
- **预期**：
  - ① 第二张卡片右上角显示"😄 幽默"
  - ② 风格选择会被记到 conv.defaultStyleId，下次进入该 crush 默认就是"幽默"

### TC-4.7 时间分隔（5 分钟规则）
- **操作**：连发 2 条间隔 < 5 分钟 → 等 6 分钟再发 1 条
- **预期**：
  - ① 第一条上方显示时间"今天 HH:MM"
  - ② 第二条上方无时间
  - ③ 第三条上方显示时间"今天 HH:MM"

## 🟡 模块 6：删除与重试

### TC-6.1 长按消息 → 删除
- **操作**：长按任意一轮 → 弹"删除这一轮对话" → 确认
- **预期**：
  - ① 整一轮（crush 气泡 + AI 卡片）一起删掉
  - ② toast "已删除"
  - ③ 返回首页该 crush 的预览同步更新到上一轮的内容

### TC-6.2 删除最后一轮 → 首页预览清空
- **操作**：聊天页删到一条都不剩 → 返回首页
- **预期**：首页该 crush 的预览显示"还没有聊天，快开始吧"

### TC-6.3 AI 生成失败重试
- **操作**：拔掉网 → 发送 → 等错误卡片出现 → 接上网 → 点"点击重试"
- **预期**：
  - ① 错误卡片：⚠️ + 错误说明 + 红色"点击重试"按钮
  - ② 点重试后这张卡片被替换为新的"思考中"
  - ③ 生成成功后变回正常绿色卡片

### TC-6.4 卡住的临时消息也能删
- **场景**：sending 卡住、网络异常等导致 temp- 开头的消息
- **操作**：长按该消息 → 删除
- **预期**：能从本地列表删掉（不调数据库）

### TC-6.5 再来 N 条失败 → 点"⚠️ 失败，点击重试"
- **操作**：网络断 → 点"再来 N 条"
- **预期**：
  - ① 思考中变为 ⚠️ 失败按钮
  - ② 点击重试能重新生成
  - ③ 不影响已有那条 suggestion

## 🟡 模块 7：内容安全与异常

### TC-7.1 用户输入触发安全检测
- **操作**：粘贴明显违规内容（如政治敏感词、辱骂等）→ 发送
- **预期**：
  - ① 错误卡片显示"输入内容包含敏感词，请修改后重试"
  - ② 不会调用 DeepSeek 浪费 token
- **建议**：测试时用文档示例敏感词清单

### TC-7.2 AI 输出触发安全检测
- **操作**：用户输入正常但风格选"撩拨"+ 极端语境，可能触发
- **预期**：错误卡片显示"AI 生成的内容触发了安全检测，请换个说法或换个风格重试"

### TC-7.3 没设置 DEEPSEEK_API_KEY
- **环境**：云函数环境变量未配
- **操作**：发送
- **预期**：错误卡片显示"请在云开发后台... 设置 DEEPSEEK_API_KEY"

### TC-7.4 网络断开
- **操作**：飞行模式 → 发送
- **预期**：错误卡片显示 errMsg（网络相关）

### TC-7.5 styles 表权限错误
- **场景**：styles 表权限不是"所有用户可读"
- **预期**：聊天页底部显示红色"⚠️ 风格未加载（共 0 条）。请确认 styles 表..."

## 🟢 模块 8：长期记忆（隐藏功能，PM 抽查）

### TC-8.1 聊够 20 轮后摘要触发
- **操作**：和一个 crush 连续聊 21 轮（每轮一条消息）
- **预期**：
  - ① 第 20 轮后云端开始有摘要（前端无感）
  - ② 第 21 轮 AI 回复时能记住前面聊过的话题（即使前 10 轮已经被压缩）
  - ③ 通过云开发后台 → conversations 表 → 找该 conv → 应该看到字段 `memorySummaries`（数组）和 `crushInsights`（字符串）

### TC-8.2 删消息后再聊（**修复后回归 BUG-1**）
- **操作**：
  - ① 先聊 25 轮触发摘要 → `lastSummarizedCount=25`
  - ② 删除 10 轮（保留 15 轮）
  - ③ 再聊 5 轮（总共 20 轮）
  - ④ 期间云函数 summarizeMemory 触发
- **预期（修复后）**：
  - ① 云函数日志能看到 `reason: 'realigned'` 一次
  - ② 之后再聊 20 轮，摘要会重新触发
- **失败现象（修复前 / 回归用）**：永远不再生成新摘要

### TC-8.3 多个 crush 的记忆互不污染
- **操作**：给 crush A 聊到产生摘要 → 切到 crush B 重新聊
- **预期**：crush B 的 prompt 里看不到 A 的摘要（按 conversationId 隔离）

## 🟢 模块 10：多设备 / 多账号边界

### TC-10.1 同一微信号在不同设备登录

| 风险点 | 说明 | 应对 |
|---|---|---|
| **首次部署后 styles 权限** | 默认是"仅创建者读写"，必须改成"所有用户可读" | 部署完 init 后立刻去后台改权限 |
